# hstun

ترافیک TCP را از داخل یک اتصال HTTPS معمولی عبور می‌دهد. همهٔ بایت‌ها در نشست‌های چندکاناله، احراز هویت‌شده و رمزنگاری سرتاسری حمل می‌شوند؛ به این ترتیب چند اتصال TLS می‌تواند هر تعداد جریان TCP را جابه‌جا کند. از TLS واقعی با ClientHello شبیه مرورگر (uTLS)، ارتقای واقعی WebSocket یا درخواست‌های POST واقعی، دست‌دهی احراز هویت‌شده و یک وب‌سایت طعمه استفاده می‌کند و طوری ساخته شده که شناسایی و مسدودسازی‌اش برای DPI سخت باشد. فهرست کارهای انجام‌شده و آنچه بعداً اندازه‌گیری می‌شود در [docs/stealth-plan.md](docs/stealth-plan.md) است.

</div>

```
 users  ──▶  ENTRY host           ══ HTTPS (WebSocket or HTTP) ══▶   EXIT host          ──▶  your proxy
             (restricted side)       one pair of hosts, one secret      (outside)               (e.g. a VLESS inbound)
             listens on :20151                                          listens on :443         on 127.0.0.1:19990
```

<div dir="rtl" lang="fa">

- **خروجی (Exit)**: سرورِ بیرون از شبکهٔ محدودشده. تونل را دریافت می‌کند و ترافیک را به پروکسی شما می‌رساند.
- **ورودی (Entry)**: سرورِ داخل شبکهٔ محدودشده. کاربران (یا کلاینت‌های پروکسی شما) به آن وصل می‌شوند.

نسخهٔ 0.5.0. پیش‌انتشار (pre-release) و بدون ممیزی مستقل. جزئیات: [docs/security.md](docs/security.md) (به انگلیسی).

> فقط این صفحه ترجمه شده است؛ بقیهٔ مستندات (`docs/`) انگلیسی‌اند. اگر بین دو نسخه تفاوتی بود، نسخهٔ انگلیسی مرجع است.

## شروع سریع

روی هر دو سرور با کاربر root اجرا کنید (ابتدا `sudo -i`). یک دستور، یک منو، روی هر دو سرور یکسان:

</div>

```bash
bash <(curl -Ls https://raw.githubusercontent.com/HamidrezaTg/hstun/main/install.sh)
```

<div dir="rtl" lang="fa">

۱. **روی سرور بیرون** گزینهٔ *Install an exit* را بزنید. می‌پرسد حالت چیست (nginx همراه با دامنه توصیه می‌شود)، پروکسی شما کجا گوش می‌دهد، و همه‌چیز را نصب می‌کند. در پایان **یک دستور** برای سرور دیگر چاپ می‌کند.

۲. **روی سرور محدودشده** همان دستور را اجرا کنید (شکلش `hstun-ctl entry --join 'hstun-pair:...'` است؛ اگر `hstun-ctl` هنوز آنجا نصب نیست، خروجی همان دستور را با نصب‌کنندهٔ یک‌خطی در ابتدایش هم چاپ می‌کند). این کد **حاوی رمز (secret)** است، پس آن را فقط از مسیر خصوصی بفرستید. انتخاب کنید چه کسی به ورودی وصل شود (همه، یا فقط همین سرور).

۳. **کلاینت‌های پروکسی را به** `ENTRY-HOST:20151` **وصل کنید.** با `hstun-ctl test` بررسی کنید.

پیش از گام ۱ باید روی سرور بیرون یک پروکسی در حال گوش دادن باشد، مثلاً یک inbound از نوع VLESS روی `127.0.0.1:19990` در x-ui یا xray. hstun جریان خام TCP را به آن می‌رساند و خودش آن را نصب نمی‌کند. روش انتقال پیش‌فرض WebSocket (`ws`) است و خودکار انتخاب می‌شود.

## کدام حالت را انتخاب کنم؟

| وضعیت | حالت خروجی (exit mode) | روش انتقال (carrier) |
|---|---|---|
| دامنه دارید و می‌توانید nginx اجرا کنید | `nginx` (توصیه‌شده: شبیه یک وب‌سایت معمولی است) | `ws` |
| فقط آدرس IP دارید و کمترین تعداد قطعه می‌خواهید | `direct` (گواهی خودامضا که ورودی آن را «پین» می‌کند) | `ws` |
| از قبل Cloudflare Tunnel دارید | `cloudflared` | `chunk` اگر در مسیر شما اتصال‌های طولانی به Cloudflare قطع می‌شوند، وگرنه `ws` |
| WebSocket در مسیر مسدود است | هر حالتی | `http` |
| مطمئن نیستید کدام کار می‌کند | هر حالتی | `auto`: خودش به‌ترتیب ws، http، chunk را امتحان می‌کند و از مسیر بسته رد می‌شود |

روش انتقال را روی ورودی با `--carrier ws|http|chunk|auto` عوض می‌کنید. هر کدام از `ws`، `http` و `chunk` تنها هم قابل انتخاب است؛ `auto` فقط گزینهٔ چهارمی است که بین همین‌ها جابه‌جا می‌شود. جزئیات: [docs/modes-and-carriers.md](docs/modes-and-carriers.md).

## استفادهٔ روزانه

| دستور | کار |
|---|---|
| `hstun-ctl` | منو: نشان می‌دهد روی این سرور چه نصب است و فقط کارهایی را که معنا دارند |
| `hstun-ctl status` / `test` / `doctor` | وضعیت؛ آزمون سرتاسری؛ بررسی سرور (فایروال، گواهی، DNS، ساعت...) |
| `hstun-ctl logs [-f]` / `restart` | لاگ؛ راه‌اندازی مجدد |
| `hstun-ctl edit` | تغییر تنظیمات؛ اگر تونل برنگردد خودکار لغو می‌شود |
| `hstun-ctl update` / `rollback` | آخرین نسخه (در صورت شکست خودش برمی‌گردد) / نسخهٔ قبلی |
| `hstun-ctl show-join` | دوباره کد جفت‌سازی (`--no-secret` برای نسخهٔ بدون رمز) |
| `hstun-ctl backup` / `restore FILE [--test]` | یک آرشیو خصوصی از همهٔ نمونه‌ها / بررسی و بازیابی آن |
| `hstun-ctl rotate-secret` / `pin VERSION` | رمز جدید بدون قطعی / نگه داشتن همهٔ سرورها روی یک نسخه |
| `hstun-ctl uninstall [--purge]` | حذف یک نمونه |

همه‌چیز پرچم (flag) هم دارد و بدون پرسش اجرا می‌شود (`--yes`): [docs/install.md](docs/install.md). اجرای دوبارهٔ نصب‌کننده روی سروری که نصب است می‌پرسد نگه دارم، تغییر بدهم یا از نو نصب کنم: گواهی، رمز و مسیرها در «تغییر» حفظ می‌شوند، بنابراین ورودی‌هایی که قبلاً جفت شده‌اند کار می‌کنند. سرویس‌هایی که با دست راه انداخته‌اید را `hstun-ctl adopt` در اختیار می‌گیرد ([docs/operations.md](docs/operations.md)).

## توقف مرتب و محدودیت‌ها

- **توقف مرتب:** با `restart`، `update` یا `systemctl stop` ابتدا پورت‌ها بسته می‌شوند و فقط جریان‌هایی که در جریان‌اند تا `drain_timeout` (پیش‌فرض ۱۰ ثانیه) فرصت پایان دارند. اتصال‌های بسیار طولانی بعد از آن قطع می‌شوند و دو سر آن‌ها «reset» می‌بینند، نه پایان عادی. با `--drain-timeout 0s` رفتار قدیمی برمی‌گردد.
- **قطع‌شدن دیده می‌شود:** اگر یک سمت اتصال reset شود یا نشست تونل وسط انتقال بمیرد، سمت دیگر هم reset می‌بیند و آن را یک انتقال کامل تصور نمی‌کند.
- **محدودیت برای هر کلید (روی خروجی):** `--max-mbit N` پهنای باند هر جهت و `--max-new-streams N` تعداد جریان جدید در ثانیه را برای هر رمز محدود می‌کند. وقتی ورودی بدرفتاری کند یا رمزش لو برود از خروجی محافظت می‌کند.

## پیش‌نیازها

لینوکس با systemd (روی Debian/Ubuntu آزموده شده؛ dnf، yum و pacman هم پشتیبانی می‌شوند)، x86-64 یا arm64، و دسترسی root. اگر `curl`، `tar`، `openssl` و `jq` نباشند نصب می‌شوند. حالت `nginx` به دامنه‌ای نیاز دارد که به این سرور اشاره کند و یک گواهی (فایل‌های خودتان، یا `--acme` با certbot و آزاد بودن پورت ۸۰). نصب‌کننده پورتش را در `ufw` باز می‌کند و سقف اتصال برای هر منبع می‌گذارد؛ با فایروال دیگر (یا فایروال ابری) پورت را خودتان باز کنید. جدول کامل: [docs/install.md](docs/install.md).

## مشکل دارید؟

اول `hstun-ctl doctor`، بعد [docs/troubleshooting.md](docs/troubleshooting.md): نبودن نشست تونل، بالا بودن تونل ولی بدون ترافیک، هشدار SNI، پورت اشغال، certbot، شکست به‌روزرسانی.

## امنیت در یک نگاه

- پس از دست‌دهی متقابل HMAC، هر بایت با AES-256-GCM و کلیدهایی رمز می‌شود که فقط دو سر hstun دارند؛ CDN یا پروکسی میانی فقط قاب‌بندی HTTP را می‌بیند، نه داده را.
- رمز یک فایل با دسترسی 0600 است و هرگز چاپ نمی‌شود. تنها جایی که رمز جابه‌جا می‌شود کد جفت‌سازی است: با آن مثل یک گذرواژه رفتار کنید.
- سرور به هر چیزی که آن دو مسیر مخفی نباشد با یک وب‌سایت معمولی (طعمه) جواب می‌دهد. اتصال‌ها، دست‌دهی‌ها و شکست‌های احراز هویت برای هر آدرس محدود می‌شوند.
- کلاینت ClientHello یک مرورگر واقعی را می‌فرستد (`tls_fingerprint`؛ پیش‌فرض Chrome، و `go` آن را خاموش می‌کند)، پس اثر انگشت JA3/JA4 دیگر نمی‌گوید «یک برنامهٔ Go». hstun همچنان پنهان نمی‌کند که شما از HTTPS به یک سرور استفاده می‌کنید؛ برای اینکه ناظر هنوز چه چیزهایی را می‌تواند بفهمد [docs/security.md](docs/security.md) را بخوانید.
- گزارش آسیب‌پذیری: [SECURITY.md](SECURITY.md) (گزارش خصوصی، نه Issue عمومی).
